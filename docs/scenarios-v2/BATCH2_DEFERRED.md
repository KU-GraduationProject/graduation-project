# 2차 B군 — 설계만 (코드 없음)

> 아래 시나리오는 **지금 관측 경로가 없거나 안전 설계가 먼저 필요**해 구현하지 않았다.
> 지금 주입하면 "증거 없음"이 돼 평가 데이터가 오염된다. 각 항목: 위협 정의 / 필요한 관측 / 주입 초안 / 정답 / 안전 위험.
> 정답은 확정 전 초안이며, 구현할 때 `scenarios/v2/registry.py` 로 옮긴다(단일 출처).

## S1-d — 파일 경로 남용 (`/files/` 대량)
- **위협:** 공개 파일 경로(nginx → MinIO 프록시)로 객체를 대량·열거식으로 내려받는다(스크래핑·반출).
- **필요한 관측:** nginx → MinIO 구간은 Zeek 브리지 캡처(backend netns) 밖이다. (a) nginx 액세스 로그의 `/files/` 요청량·바이트 집계를 룰 입력으로 쓰거나, (b) MinIO 감사 로그/메트릭(`minio_s3_requests_total`, 전송 바이트)을 수집해야 보인다.
- **주입 초안:** 측정 PC 에서 기존 공개 객체 키 목록(앱 API 로 얻은 것만)을 반복 GET. 없는 키 열거(404 다발)는 S1-b 와 겹치므로 별도 변형으로.
- **정답(초안):** `medium` / `NOTIFY` / *BLOCK_PATH*. ATT&CK 후보 T1530(확인 필요).
- **안전 위험:** 읽기만 — 객체 변경 없음. 대역폭 포화로 정상 사용자 영향 → 동시성 상한·워치독 필요.

## S3-a — 다른 컨테이너 직접 접속 (lateral)
- **위협:** 침해된 컨테이너가 backend 를 거치지 않고 다른 내부 서비스(DB·MinIO 관리 포트)에 직접 접속한다.
- **필요한 관측:** 현재 캡처는 backend netns 하나뿐이라 backend 외 출발지는 보이지 않는다. leafy-net **브리지 전체 캡처**(호스트 측 bridge 인터페이스 또는 서비스별 Zeek) 추가가 필요.
- **주입 초안:** frontend(또는 전용 테스트 컨테이너) netns 사이드카에서 db:5432 / minio:9000 으로 인증 없이 연결 시도.
- **정답(초안):** `high` / `ISOLATE` / *ISOLATE*. ATT&CK 후보 T1021 계열(확인 필요).
- **안전 위험:** 인증 시도 금지(연결만). 실제 자격증명 사용 금지.

## S3-b — 무단 컨테이너 접속 (exec·신규 컨테이너)
- **위협:** 누군가 운영 컨테이너에 `docker exec` 로 셸을 열거나 낯선 컨테이너를 붙인다.
- **필요한 관측:** 브리지 캡처 + **Docker 이벤트 스트림**(exec_create/exec_start, container create/attach) 수집기. 현재 없음.
- **주입 초안:** backend 에 무해 명령 `docker exec ... id` 1회 + 낯선 이름의 일회용 컨테이너를 leafy-net 에 잠깐 붙였다 제거.
- **정답(초안):** `high` / `NOTIFY` / *ISOLATE*. ATT&CK 후보 T1609(확인 필요).
- **안전 위험:** 셸 명령은 읽기 전용 무해 명령만. 일회용 컨테이너는 --rm + 워치독 제거.

## F2-e — 앱 커넥션 풀 누수
- **장애:** 앱 코드가 커넥션을 반납하지 않아 **HikariCP 풀**이 고갈된다(DB 서버 한도가 아니라 앱 풀 — F2-c 와 구분).
- **필요한 관측:** HikariCP 메트릭(`hikaricp_connections_active/pending`, `..._timeout_total`)을 actuator/prometheus 로 노출·수집. 현재 수집 여부 미확인.
- **주입 초안:** (a) dev 프로파일 전용 테스트 훅(커넥션 N개 빌리고 안 돌려주는 엔드포인트) — 앱 수정 필요, 또는 (b) JVM 에이전트로 반납 지연. 둘 다 앱/이미지 변경이 필요해 별도 이슈.
- **정답(초안):** `high` / `RESTART` / *RESTART*.
- **안전 위험:** 테스트 훅은 dev 프로파일에서만 활성화, 운영 이미지에 포함 금지. 원본 이미지 고정 규칙과 충돌하지 않게 별도 태그 정책 필요.

## F2-b DB 중단·지연 / F1-d 저장 공간 고갈 / F2-d 외부 API 장애 — 안전 설계 먼저
- **F2-b:** 측정 PC DB 는 호스트 서비스(Windows PostgreSQL)일 수 있다. 서비스 중지·네트워크 지연(tc)은 호스트 권한·자동 복구 경로가 필요. 정답(초안) `high` / `NOTIFY` / *RESTART*. 필요 관측: postgres-exporter `pg_up`·지연 메트릭, 앱 연결 오류 로그.
- **F1-d:** 호스트/볼륨 디스크를 채우면 DB·MinIO 데이터 손상 위험. **전용 tmpfs/루프백 볼륨**에서만 하고 실데이터 볼륨은 금지하는 설계가 먼저. 정답(초안) `high` / `NOTIFY` / *NOTIFY*. 필요 관측: node-exporter 파일시스템 여유 공간, 쓰기 실패 로그.
- **F2-d:** 외부 API 를 실제로 끊으려면 egress 차단(방화벽·DNS) 이 필요 — 다른 서비스까지 영향. backend netns 한정 차단 + 워치독 해제 설계가 먼저. 정답(초안) `medium` / `NOTIFY` / *NOTIFY*. 필요 관측: 외부 호출 오류 로그·네트워크 이벤트(연결 실패).
