## Decided
- source-aware 룰팩의 집계는 site/source/service/runtime/target/name을 유지한다. #61 이후 원본 식이 by(name)에서 by(site,name)으로 바뀌어 release 재작성 정규식이 빗나가고 동적 메모리 경보의 대상이 사라졌다. 두 형태를 모두 재작성하고 native promtool 회귀로 확인한다.
- DB 읽기 급증과 로그인 실패 집계는 NONE/NOTIFY만 허용한다. 전자는 정상 백업도 같은 신호를 내고 후자는 계정 identity가 없어 컨테이너/세션/계정을 추정해 조치하면 오조치다. 새로운 네트워크 신호는 검증된 observer와 정확한 출발 컨테이너에 묶고 기존 실행기로 수동 승인한다.
## Tried and ruled out
- 원본 집계가 항상 by(name)이라고 가정: native source-identity/메모리 경보 테스트에서 runtime/service/target이 사라짐.
- DB 통계만 보고 backend ISOLATE나 KILL_SESSIONS로 연결: 관측 대상은 host DB이며 공격 출발지·세션 선택 증거가 없음.
## Watch out
- LogCLI stdin은 실제 stream label 선택과 Loki range 집계를 검증하지 않는다. 정상 대조·실제 Ruler 평가/발화·승인·효과/복구는 별도 실환경 인수다.
